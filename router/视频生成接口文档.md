# 视频生成接口文档

## 概述

本文档描述了 Nebula API 中视频生成接口的架构、适配器实现和统一的入参出参设计。系统支持多种视频生成服务，包括可灵AI (Kling)、即梦 (Jimeng)、豆包 (Doubao)、Vidu 和 Suno 等。

## 接口架构

### 路由结构

系统提供了多层次的视频生成接口：

#### 1. 统一视频生成接口
```
POST /v1/video/generations          # 提交视频生成任务
GET  /v1/video/generations/:task_id # 查询任务状态
```

#### 2. 各厂商专用接口

**可灵AI (Kling)**
```
POST /kling/v1/videos/text2video    # 文生视频
POST /kling/v1/videos/image2video   # 图生视频
GET  /kling/v1/videos/text2video/:task_id
GET  /kling/v1/videos/image2video/:task_id
```

**豆包 (Doubao)**
```
POST /doubao/v1/videos/text2video   # 文生视频
POST /doubao/v1/videos/image2video  # 图生视频
GET  /doubao/v1/videos/text2video/:task_id
GET  /doubao/v1/videos/image2video/:task_id
```

**即梦 (Jimeng)**
```
POST /jimeng/                       # 统一提交接口
```

## 适配器实现

### 支持的视频生成适配器

| 适配器 | 厂商 | 支持功能 | 模型列表 |
|--------|------|----------|----------|
| Kling | 可灵AI | 文生视频、图生视频 | kling-v1, kling-v1-6, kling-v2-master |
| Jimeng | 即梦 | 文生视频、图生视频 | jimeng_vgfm_t2v_l20 |
| Doubao | 豆包 | 文生视频、图生视频 | doubao-video |
| Vidu | Vidu | 文生视频、图生视频 | vidu-video |
| Suno | Suno | 音乐生成 | suno-music |

### 适配器接口规范

所有视频适配器都实现了 `TaskAdaptor` 接口：

```go
type TaskAdaptor interface {
    Init(info *relaycommon.RelayInfo)
    ValidateRequestAndSetAction(c *gin.Context, info *relaycommon.RelayInfo) *dto.TaskError
    BuildRequestURL(info *relaycommon.RelayInfo) (string, error)
    BuildRequestHeader(c *gin.Context, req *http.Request, info *relaycommon.RelayInfo) error
    BuildRequestBody(c *gin.Context, info *relaycommon.RelayInfo) (io.Reader, error)
    DoRequest(c *gin.Context, info *relaycommon.RelayInfo, requestBody io.Reader) (*http.Response, error)
    DoResponse(c *gin.Context, resp *http.Response, info *relaycommon.RelayInfo) (taskID string, taskData []byte, taskErr *dto.TaskError)
    FetchTask(baseUrl, key string, body map[string]any) (*http.Response, error)
    ParseTaskResult(respBody []byte) (*relaycommon.TaskInfo, error)
    GetModelList() []string
    GetChannelName() string
}
```

## 统一入参出参设计

### 统一请求参数 (VideoRequest)

```json
{
  "model": "kling-v1",                    // 模型名称
  "prompt": "宇航员站起身走了",             // 文本提示词
  "image": "https://example.com/image.jpg", // 图片输入 (URL/Base64)
  "duration": 5.0,                        // 视频时长 (秒)
  "width": 512,                           // 视频宽度
  "height": 512,                          // 视频高度
  "fps": 30,                              // 帧率
  "seed": 20231234,                       // 随机种子
  "n": 1,                                 // 生成视频数量
  "response_format": "url",               // 响应格式
  "user": "user-1234",                    // 用户标识
  "metadata": {                           // 厂商特定参数
    "negative_prompt": "blurry, low quality",
    "cfg_scale": 0.7,
    "mode": "std",
    "aspect_ratio": "16:9"
  }
}
```

### 统一响应参数

#### 任务提交响应 (VideoResponse)
```json
{
  "task_id": "abcd1234efgh",             // 任务ID
  "status": "submitted"                  // 任务状态
}
```

#### 任务查询响应 (VideoTaskResponse)
```json
{
  "task_id": "abcd1234efgh",             // 任务ID
  "status": "succeeded",                 // 任务状态: submitted/queued/in_progress/succeeded/failed
  "url": "https://example.com/video.mp4", // 视频资源URL (成功时)
  "format": "mp4",                       // 视频格式
  "metadata": {                          // 结果元数据
    "duration": 5.0,                     // 实际生成的视频时长
    "fps": 30,                           // 实际帧率
    "width": 512,                        // 实际宽度
    "height": 512,                       // 实际高度
    "seed": 20231234                     // 使用的随机种子
  },
  "error": {                             // 错误信息 (失败时)
    "code": 400,
    "message": "Invalid prompt"
  }
}
```

## 任务状态说明

| 状态 | 说明 | 进度 |
|------|------|------|
| submitted | 任务已提交 | 10% |
| queued | 任务排队中 | 20% |
| in_progress | 任务处理中 | 30% |
| succeeded | 任务成功完成 | 100% |
| failed | 任务失败 | 100% |

## 中间件转换

系统通过中间件实现不同厂商接口到统一接口的转换：

### Kling 中间件
- 路径：`middleware/kling_adapter.go`
- 功能：将 Kling 专用参数转换为统一格式
- 支持：文生视频、图生视频

### Doubao 中间件
- 路径：`middleware/doubao_adapter.go`
- 功能：将豆包专用参数转换为统一格式
- 支持：文生视频、图生视频

### Jimeng 中间件
- 路径：`middleware/jimeng_adapter.go`
- 功能：将即梦专用参数转换为统一格式
- 支持：文生视频、图生视频

## 异步任务处理

### 任务更新机制
系统通过 `UpdateVideoTaskAll` 函数定期更新所有视频生成任务的状态：

1. **批量获取任务**：按渠道分组获取待处理任务
2. **调用适配器**：使用各厂商适配器查询任务状态
3. **状态更新**：更新任务状态、进度和结果
4. **错误处理**：处理失败任务，退还配额

### 任务生命周期
```
提交任务 → 排队中 → 处理中 → 完成/失败
    ↓         ↓        ↓        ↓
  10%       20%      30%      100%
```

## 开发者使用指南

### 1. 统一接口调用

```bash
# 提交视频生成任务
curl -X POST "http://localhost:3000/v1/video/generations" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{
    "model": "kling-v1",
    "prompt": "一只可爱的小猫在花园里玩耍",
    "duration": 5.0,
    "width": 512,
    "height": 512,
    "metadata": {
      "aspect_ratio": "16:9",
      "mode": "std"
    }
  }'

# 查询任务状态
curl -X GET "http://localhost:3000/v1/video/generations/task_id" \
  -H "Authorization: Bearer YOUR_TOKEN"
```

```bash
# 可灵AI 文生视频

  -d '{
    "model_name": "kling-v1",
    "prompt": "A cat playing piano in the garden",
    "aspect_ratio": "16:9",
    "duration": "5"
  }'
```

### 3. 图生视频示例

```bash

  -H "Content-Type: application/json" \
```

## 错误处理

### 常见错误码

| 错误码 | 说明 | 解决方案 |
|--------|------|----------|
| 400 | 请求参数错误 | 检查请求参数格式和必填字段 |
| 401 | 未授权 | 检查认证令牌是否有效 |
| 403 | 无权限 | 检查用户权限和配额 |
| 429 | 请求频率限制 | 降低请求频率 |
| 500 | 服务器内部错误 | 联系技术支持 |

### 错误响应格式

```json
{
  "error": {
    "message": "Invalid request parameters",
    "type": "invalid_request_error",
    "code": "invalid_request"
  }
}
```

## 最佳实践

### 1. 模型选择
- **文生视频**：推荐使用 `kling-v1` 或 `kling-v2-master`
- **图生视频**：推荐使用 `kling-v2-master`
- **音乐生成**：使用 `suno-music` 相关模型

### 2. 参数优化
- **提示词**：使用清晰、具体的描述
- **时长**：根据需求选择合适的视频时长
- **分辨率**：平衡质量和处理时间
- **种子**：使用固定种子确保结果可重现

### 3. 异步处理
- 提交任务后立即获取 `task_id`
- 定期轮询任务状态
- 处理失败情况并重试

### 4. 配额管理
- 监控用户配额使用情况
- 合理设置请求频率
- 处理配额不足的情况

## 扩展开发

### 添加新的视频适配器

1. **创建适配器文件**：在 `relay/channel/task/` 下创建新目录
2. **实现接口**：实现 `TaskAdaptor` 接口的所有方法
3. **注册适配器**：在 `relay/relay_adaptor.go` 中注册新适配器
4. **添加中间件**：如需要，创建专用中间件进行参数转换
5. **测试验证**：编写测试用例验证适配器功能

## 总结

Nebula API 的视频生成接口提供了统一的调用方式，支持多种视频生成服务。通过适配器模式和中间件转换，开发者可以使用统一的参数格式调用不同厂商的视频生成服务，大大简化了集成复杂度。

系统采用异步任务处理机制，支持长时间的视频生成任务，并提供完整的任务状态跟踪和错误处理机制。开发者可以根据需求选择合适的接口和参数，实现高质量的视频生成功能。
